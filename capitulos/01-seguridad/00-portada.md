# Antes de empezar

## Para quién es

Para quien hace webs o las encarga y quiere entender **qué protege cada cosa y por qué**, sin
necesidad de ser experto en seguridad. Si estás empezando a programar, si delegas mucho trabajo en
una IA y necesitas saber si lo que te entrega está bien, o si tienes que hablar con un proveedor y no
quieres que te la cuelen, este capítulo es para ti.

No hace falta saber programar para seguirlo. Los fragmentos de código son pocos, cortos y opcionales:
van marcados como **«Para quien quiera ver código»** y puedes saltártelos.

## Cómo está organizado

Cada apartado sigue el mismo orden:

| Parte | Qué contiene |
|---|---|
| **La idea** | Una comparación con algo cotidiano para entender el concepto |
| **Qué puede salir mal** | El ataque o el fallo real, contado sin jerga |
| **Cómo se hace bien** | Lo que hay que hacer, con los valores concretos |
| **Cómo comprobarlo** | Una prueba que puedes hacer tú para saber si está bien |

Al final tienes una **chuleta de parámetros** (apartado 10) y una **lista para revisar una web antes
de publicarla** (apartado 11). Si solo tienes cinco minutos, ve directamente allí.

## Contenido del capítulo

1. Cómo piensa un atacante
2. Los diez fallos más comunes (OWASP Top 10:2025)
3. Cuentas, contraseñas y sesiones
4. El navegador: HTTPS, cabeceras, XSS, CSRF y CORS
5. Lo que entra: formularios, consultas, archivos y límites
6. Pagos online
7. Secretos, configuración y dependencias
8. Si tu web usa inteligencia artificial
9. Vigilar, copiar y reaccionar
10. Chuleta de parámetros
11. Lista de revisión antes de publicar
12. Fuentes

## Aviso

Este capítulo resume buenas prácticas publicadas por organismos de referencia (OWASP, NIST, MDN,
INCIBE, entre otros) a noviembre de 2026. **No sustituye una auditoría profesional ni un consejo
legal.** La seguridad cambia: antes de aplicar una cifra, mira la fecha y la fuente que la acompañan.
